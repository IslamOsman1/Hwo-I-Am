# تحدي المعلومات — تشغيل السيرفر

## خمن علم الدولة — 4.1

- لعبة أصلية مستقلة: `create` مع `gameId: "flags"` دون `packId`.
- ١٩٥ دولة (١٩٣ عضوًا بالأمم المتحدة مع فلسطين والفاتيكان). صور PNG مضمنة
  في بنك السيرفر؛ لا يوجد طلب لموقع صور خارجي أثناء السؤال.
- يقبل اسم الدولة بالعربي والإنجليزي، مع بدائل شائعة مثل «السعودية» و«أمريكا».
- النقاط والوقت والصوت والخصوصية وتصحيح الهوست تطبق بنفس قواعد تحدي المعلومات.
- كل غرفة جديدة تختار مجموعة وترتيب أسئلة عشوائيين باستخدام `crypto.randomInt`،
  للباقات والأعلام. لا يتكرر سؤال داخل الجولة؛ الرجوع للغرفة يحفظ نفس الترتيب.
- المصادر: https://flagpedia.net/download/api (صور FlagCDN المبنية على Wikimedia).
  تفاصيل المصدر والأكواد محفوظة في `data/flags-source.json`.

## أصدقاء وصلاحيات 4.0

- إنشاء وتعديل ونشر الباقات للأدمن فقط، بفحص `role` من قاعدة البيانات لكل طلب؛
  إخفاء زر الباقات في التطبيق ليس بديلًا عن صلاحية السيرفر. اللاعب العادي يستطيع
  استضافة ولعب الباقات المنشورة، لكنه لا يستطيع إنشاء باقة أو تعديلها.
- الأصدقاء: بحث بالاسم أو كود الصداقة دون كشف الإيميل، إرسال/قبول/رفض/إلغاء الطلب
  وإزالة صديق. العلاقة لا تصبح صداقة إلا بقبول الشخص المستلم.
- خصوصية الغرفة `anyone` تعني الدخول بالكود، `friends` للأصدقاء المقبولين،
  و`invite` للدعوات الصريحة. القيود تُطبق على طلب الدخول في السيرفر.
- الهوست يستطيع إرسال دعوة من الغرفة لصديق مقبول؛ تظهر الدعوة في تبويب الأصدقاء.
  دعوات الغرف تنتهي بعد ساعتين، وقد تصبح غير صالحة إذا انتهت الغرفة أو أعيد نشر
  الخدمة المجانية. امتلاك كود الغرفة وحده لا يتجاوز قيود الأصدقاء والدعوات.
- الاتصال صوت فقط؛ عميل Android لا يطلب الكاميرا ولا يفاوض استقبال فيديو.
- إعداد الأدمن لأول مرة: ضع `ADMIN_EMAIL` و`ADMIN_BOOTSTRAP_PASSWORD` في Environment
  فقط. إذا كان الإيميل مسجلًا بالفعل، يجب أن يطابق الباسورد الحالي قبل منحه الصلاحية.
  بعد نجاح أول دخول للأدمن، امسح قيمة متغير الباسورد؛ الصلاحية والبصمة تحفظهما MongoDB.
  لا تضف هذه القيم إلى Git أو APK، ولا توجد ترقية صلاحية من طلب التسجيل العام.

واجهات الأصدقاء: `GET /api/people?q=...`, `GET /api/friends`,
`POST /api/friends/:id` مع `action=request|accept|decline|cancel|remove`.

## حسابات وباقات 3.0

الحسابات والباقات وصورها محفوظة في MongoDB Atlas، منفصلة عن ملفات غرف Render
المؤقتة. اضبط `MONGODB_URI` و`MONGODB_DB=menana` في Environment فقط. رابط MongoDB
لا يدخل التطبيق أو GitHub. بدء السيرفر ينتظر الاتصال وإنشاء الفهارس؛ عند غياب
الربط تظل اللعبة الأصلية متاحة، وترجع واجهة الحسابات 503 بدل الادعاء بحفظ البيانات.

- حساب بالإيميل والباسورد، ملف شخصي بصورة واسم ونبذة، تغيير باسورد وتسجيل خروج.
- الباسورد محفوظ بـscrypt مع salt؛ الجلسات عشوائية محفوظة كبصمة ولها صلاحية 30 يومًا.
  تغيير الباسورد يلغي صلاحية الجلسات القديمة حتى مع طلب دخول متزامن.
- `/api/auth/register` و`/api/auth/login` و`/api/auth/logout`، و`/api/me`، و`/api/me/password`.
- الباقات: `/api/packs` للبحث العام أو `?scope=mine`، و`/api/packs/:id` للتعديل بصلاحية
  المالك فقط. كتالوج الباقات لا يرجع الأسئلة أو الإجابات. الحفظ يستخدم revision
  لمنع استبدال تعديل أحدث من جهاز آخر.
- الباقة خاصة افتراضيًا؛ يمكن لعبها من سؤال واحد. النشر العام يحتاج 13 سؤالًا،
  بحد أقصى 1000 سؤال و20 باقة للحساب و3MiB للباقة. الصور اختيارية وتُعاد معالجتها
  إلى JPEG بدون metadata، مع حدود للحجم وعدد الصور التي تُعالج في نفس الوقت.
- الغرفة تأخذ نسخة ثابتة من أسئلة الباقة عند إنشائها، فلا تتغير مباراة جارية
  عند تعديل الباقة. دعم الإجابات البديلة وقواعد 20/10 وصلاحيات التصحيح كما هي.
- البريد اسم دخول؛ لم يُضف إرسال رسائل تحقق أو استعادة باسورد عبر الإيميل.
  لا يُعرض البريد علنًا ولا يُعتبر مثبت الملكية. الصور العامة والمحتوى من مسؤولية منشئ الباقة.

`node --test --test-isolation=none` يشغّل أيضًا اختبار MongoDB مؤقتًا فعليًا عبر
`mongodb-memory-server-core` (تنزيل MongoDB في أول تشغيل للاختبارات فقط).

اللعبة الجديدة أونلاين للاعبين، باللهجة المصرية. لعبة «مين أنا» القديمة تفضل
متاحة بدون إنترنت. السيرفر هو المرجع للإجابة والوقت والنقاط.

## تشغيل محلي

يتطلب Node.js 22 أو أحدث:

```powershell
cd server
npm ci
npm test
npm start
```

`GET /health` يفحص جاهزية السيرفر، و`/ws` هو اتصال WebSocket.
للاختبار المحلي على أندرويد: `adb reverse tcp:3000 tcp:3000` ثم استخدم
`http://127.0.0.1:3000` في نسخة Flutter **debug**. النسخة release تقبل HTTPS/WSS
فقط. رابط الخدمة مدمج في التطبيق منذ 2.1.0؛ لتغييره في نسخة تطوير، ضمّنه عند البناء:

```powershell
flutter build apk --release --dart-define=TRIVIA_SERVER_URL=https://YOUR-SERVICE.onrender.com
```

على Windows إذا منع sandbox إنشاء test subprocess، استخدم
`node --test --test-isolation=none` بدل `npm test`.

## النشر على Render

الخدمة المنشورة: **https://menana-trivia.onrender.com**. فحص الصحة:
https://menana-trivia.onrender.com/health. تم التحقق عبر HTTPS/WSS بلاعبين
من نظامَي النقاط، إخفاء الإجابات، تعديل الأدمين، حساب السرعة وإعادة الاتصال.
الخطة الحالية مجانية؛ بيانات الغرف مؤقتة وقد تضيع عند إعادة التشغيل أو النشر.
الاستيقاظ بعد الخمول قد يتأخر 50 ثانية أو أكثر؛ التطبيق ينتظر حتى 90 ثانية.
تم ربط Metered TURN ببيانات `MenAna Render` داخل Environment في Render فقط،
على تجربة مجانية 500MB بدون بطاقة دفع. لم تُختبر مكالمة فعلية بين موبايلين بعد.

1. ارفع المشروع إلى مستودع Git خاص بك.
2. من Render اختار New → Blueprint، ثم المستودع وملف `render.yaml` في الجذر.
3. الملف يختار **الخطة المجانية** ومسار `./storage` المؤقت. للحفظ الدائم، غيّر
   الخطة بعد مراجعة تكلفتها وأضف قرصًا دائمًا، ثم غيّر `DATA_DIR` لمسار القرص.
4. اضبط `TURN_URLS` و`TURN_SECRET` لو عندك coturn، أو اتركهما فارغين مؤقتًا لاختبار
   الأسئلة فقط. بدون TURN قد تعمل المكالمة بين بعض الشبكات وتفشل بين غيرها.
5. بعد نجاح `/health`، انسخ رابط HTTPS إلى التطبيق عند اللاعبين، أو ضمّنه بالبناء.

الملف يحدد `rootDir: server`، و`npm ci` للبناء و`npm start` للتشغيل.
احتفظ بخدمة واحدة فقط: التخزين هنا ملف JSON بمعاملات استبدال ذرية،
وليس قاعدة موزعة. لو هتشغل عدة instances، يلزم نقل المعاملات وقنوات الغرف إلى
قاعدة مشتركة قبل التوسّع. الملفات المحلية على Render لا تدوم من غير قرص دائم.
اتصال WebSocket يحتاج إعادة الاتصال عند إعادة نشر الخدمة؛ التطبيق يدعم ذلك.

المراجع: [Render WebSockets](https://render.com/docs/websocket)،
[الأقراص الدائمة](https://render.com/docs/disks)،
[Blueprint](https://render.com/docs/blueprint-spec).

## الصوت والفيديو وTURN

لو مزود الخدمة بيديك username/password بدل shared secret، اضبط `TURN_URLS`
و`TURN_USERNAME` و`TURN_CREDENTIAL`، واترك `TURN_SECRET` فارغًا. لا تضع كلمات مرور
حساب مزود الخدمة هنا؛ المطلوب بيانات TURN التي تصدرها لوحة الخدمة فقط.

المكالمات WebRTC؛ السيرفر يمرر إشارات التفاوض فقط. فتح المايك والكاميرا باختيار
اللاعب، ولا يتم تسجيل الصوت أو الفيديو على السيرفر. خروج التطبيق للخلفية أو
إغلاق الاتصال يوقف أجهزة الالتقاط. لازم اللاعبَين يفتحوا المكالمة.

استخدم خدمة coturn على VPS يدعم UDP/TCP، منفصلة عن Web Service الخاص بـRender.
مثال ملف `turnserver.conf` بعد استبدال القيم:

```ini
listening-port=3478
fingerprint
use-auth-secret
static-auth-secret=PUT_A_LONG_RANDOM_SECRET_HERE
realm=turn.YOUR-DOMAIN.com
min-port=49160
max-port=49200
no-cli
no-loopback-peers
no-multicast-peers
```

اضبط عنوان الـpublic IP/external-ip لو الـVPS خلف NAT، وافتح 3478 TCP/UDP ومدى
49160–49200 UDP. للاتصالات التي تحجب UDP أضف TURN/TLS بشهادة سليمة على 5349،
وزوّد `turns:turn.YOUR-DOMAIN.com:5349?transport=tcp` إلى `TURN_URLS`.
راجع [وثائق coturn](https://github.com/coturn/coturn/blob/master/README.turnserver).

السيرفر يولّد بيانات TURN مؤقتة لمدة 24 ساعة بـHMAC؛ السر المشترك يبقى على السيرفر
وcoturn فقط. لو المكالمة احتاجت إعادة توصيل بعد يوم، اخرج وارجع للغرفة لتجديدها.
نجاح الإشارة وحده لا يثبت عمل الميديا: قبل إطلاقها اختبر موبايلين فعليين، واحد
على شبكة موبايل والتاني Wi-Fi، بما فيها حالة استخدام TURN relay.

## القواعد والحفظ

- الجولات 1–20؛ أسئلة كل جولة 1–100؛ الوقت 5–120 ثانية.
- بنك مبدئي 340 سؤالًا أصلي الصياغة: 182 سهلًا و158 متوسطًا، في 8 مجالات.
  التاريخ مصري وعربي. `tools/build_trivia_bank.py` مصدر قابل للتحرير؛ JSON داخل
  السيرفر فقط ولا يُضمّن بالإجابات في APK.
- عدد أسئلة الجولة لازم يكون متاحًا في المجالات/المستوى المختار. السيرفر يوضح
  العدد المتاح لو الاختيار أكبر منه. لا تكرار في نفس الجولة. الأسئلة لا تتكرر
  عبر الجولات إلا بعد استنفاد البنك المختار.
- الصح 20؛ الخطأ أو عدم الإجابة صفر. لو الاتنين صح في نفس السؤال، 10 لكل واحد
  في وضع نص الدرجة، أو 20 في وضع الدرجة الكاملة، حتى مع اختلاف وقت الإجابة.
- الترتيب بالنقاط ثم أقل متوسط **أوقات الإجابات الصحيحة فقط**. التطابق الكامل
  يعطي نفس المركز. الحساب بالمللي ثانية من بداية السؤال إلى وصول الإجابة للسيرفر،
  ويتأثر بزمن الشبكة. ساعة الهاتف لا تحدد التصحيح أو النتيجة.
- الأسماء والإجابات نص حر. التطبيع يعالج المسافات والتشكيل والهمزات والأرقام العربية؛
  لا يصحح خطأ إملائيًا تخمينيًا. الإجابات البديلة مسجلة صراحة في البنك.
- الأدمين هو منشئ الغرفة. يقدر يعتمد أو يلغي صحة إجابة مكتوبة بعد كشف السؤال،
  بما فيها أسئلة سابقة والنتيجة النهائية، بسجل ظاهر للاعبين. النص والوقت الأصلي
  ثابتان، وتتحدث كل النقاط والسرعة والترتيب فورًا. لا يمنح نقاطًا لإجابة غير مرسلة.
- لا تُرسل إجابة السؤال الصحيحة ولا إجابة الخصم قبل انتهاء السؤال.
- قبل البدء يستعد اللاعبَان؛ صاحب الغرفة ينقل للسؤال التالي بعد المراجعة.
  فصل لاعب لا يوقف وقت السؤال. انتقال السؤال التالي يتطلب رجوع اللاعبَين.
- المباراة محفوظة على السيرفر ومفتاح الرجوع على نفس الموبايل. الغرف غير النشطة
  تحذف بعد 48 ساعة. حفظ المفتاح لا يغني عن الاحتفاظ بنفس بيانات التطبيق.
- المفاتيح عشوائية، المخزن يحتفظ ببصمتها فقط؛ صلاحيات التعديل من هوية الاتصال،
  مع حدود لحجم الرسالة والطلبات وعدد الاتصالات والغرف. النظام صُمم لغرف خاصة
  بين أصدقاء؛ كود الغرفة دعوة للدخول ويُشارك فقط مع اللاعب المقصود.

## التحقق قبل النشر

`npm test` يختبر القواعد واتصال عميلين حقيقيين، إخفاء الإجابات، رفض تعديل الضيف،
تعديل التصحيح والنقاط، حفظ الغرفة وإعادة تشغيل السيرفر والرجوع بمفتاحها.
اختبارات Flutter تشمل شاشة صغيرة والإجابات المكتوبة وصلاحيات الواجهة.
تم نشر السيرفر واختبار منطق اللعب عبر HTTPS/WSS. تفاصيل التحقق الفعلي وحدوده
في `DEPLOYMENT.md`؛ يلزم أيضًا تجربة مكالمة بين موبايلين على شبكتين مختلفتين.
