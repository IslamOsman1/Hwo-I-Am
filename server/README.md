# تحدي المعلومات — تشغيل السيرفر

اللعبة الجديدة أونلاين للاعبين، باللهجة المصرية. لعبة «مين أنا» القديمة تفضل
متاحة بدون إنترنت. السيرفر هو المرجع للإجابة والوقت والنقاط.

## تشغيل محلي

يتطلب Node.js 22 أو أحدث:

```powershell
cd server
npm ci
npm test
npm start
```

`GET /health` يفحص جاهزية السيرفر، و`/ws` هو اتصال WebSocket.
للاختبار المحلي على أندرويد: `adb reverse tcp:3000 tcp:3000` ثم استخدم
`http://127.0.0.1:3000` في نسخة Flutter **debug**. النسخة release تقبل HTTPS/WSS
فقط. استبدال رابط السيرفر من الشاشة متاح؛ ويمكن تضمينه عند البناء:

```powershell
flutter build apk --release --dart-define=TRIVIA_SERVER_URL=https://YOUR-SERVICE.onrender.com
```

على Windows إذا منع sandbox إنشاء test subprocess، استخدم
`node --test --test-isolation=none` بدل `npm test`.

## النشر على Render

1. ارفع المشروع إلى مستودع Git خاص بك.
2. من Render اختار New → Blueprint، ثم المستودع وملف `render.yaml` في الجذر.
3. راجع الخدمة والخطة قبل تأكيد النشر. الملف يطلب **خطة Starter مدفوعة وقرص 1GB**
   لحفظ المباريات؛ لا يوجد اشتراك أو نشر تم تلقائيًا بمجرد إضافة الملف.
4. اضبط `TURN_URLS` و`TURN_SECRET` لو عندك coturn، أو اتركهما فارغين مؤقتًا لاختبار
   الأسئلة فقط. بدون TURN قد تعمل المكالمة بين بعض الشبكات وتفشل بين غيرها.
5. بعد نجاح `/health`، انسخ رابط HTTPS إلى التطبيق عند اللاعبين، أو ضمّنه بالبناء.

الملف يحدد `rootDir: server`، و`npm ci` للبناء و`npm start` للتشغيل.
احتفظ بخدمة واحدة فقط: التخزين هنا ملف JSON بمعاملات استبدال ذرية على قرص دائم،
وليس قاعدة موزعة. لو هتشغل عدة instances، يلزم نقل المعاملات وقنوات الغرف إلى
قاعدة مشتركة قبل التوسّع. الملفات المحلية على Render لا تدوم من غير قرص دائم.
اتصال WebSocket يحتاج إعادة الاتصال عند إعادة نشر الخدمة؛ التطبيق يدعم ذلك.

المراجع: [Render WebSockets](https://render.com/docs/websocket)،
[الأقراص الدائمة](https://render.com/docs/disks)،
[Blueprint](https://render.com/docs/blueprint-spec).

## الصوت والفيديو وTURN

المكالمات WebRTC؛ السيرفر يمرر إشارات التفاوض فقط. فتح المايك والكاميرا باختيار
اللاعب، ولا يتم تسجيل الصوت أو الفيديو على السيرفر. خروج التطبيق للخلفية أو
إغلاق الاتصال يوقف أجهزة الالتقاط. لازم اللاعبَين يفتحوا المكالمة.

استخدم خدمة coturn على VPS يدعم UDP/TCP، منفصلة عن Web Service الخاص بـRender.
مثال ملف `turnserver.conf` بعد استبدال القيم:

```ini
listening-port=3478
fingerprint
use-auth-secret
static-auth-secret=PUT_A_LONG_RANDOM_SECRET_HERE
realm=turn.YOUR-DOMAIN.com
min-port=49160
max-port=49200
no-cli
no-loopback-peers
no-multicast-peers
```

اضبط عنوان الـpublic IP/external-ip لو الـVPS خلف NAT، وافتح 3478 TCP/UDP ومدى
49160–49200 UDP. للاتصالات التي تحجب UDP أضف TURN/TLS بشهادة سليمة على 5349،
وزوّد `turns:turn.YOUR-DOMAIN.com:5349?transport=tcp` إلى `TURN_URLS`.
راجع [وثائق coturn](https://github.com/coturn/coturn/blob/master/README.turnserver).

السيرفر يولّد بيانات TURN مؤقتة لمدة 24 ساعة بـHMAC؛ السر المشترك يبقى على السيرفر
وcoturn فقط. لو المكالمة احتاجت إعادة توصيل بعد يوم، اخرج وارجع للغرفة لتجديدها.
نجاح الإشارة وحده لا يثبت عمل الميديا: قبل إطلاقها اختبر موبايلين فعليين، واحد
على شبكة موبايل والتاني Wi-Fi، بما فيها حالة استخدام TURN relay.

## القواعد والحفظ

- الجولات 1–20؛ أسئلة كل جولة 1–100؛ الوقت 5–120 ثانية.
- بنك مبدئي 340 سؤالًا أصلي الصياغة: 182 سهلًا و158 متوسطًا، في 8 مجالات.
  التاريخ مصري وعربي. `tools/build_trivia_bank.py` مصدر قابل للتحرير؛ JSON داخل
  السيرفر فقط ولا يُضمّن بالإجابات في APK.
- عدد أسئلة الجولة لازم يكون متاحًا في المجالات/المستوى المختار. السيرفر يوضح
  العدد المتاح لو الاختيار أكبر منه. لا تكرار في نفس الجولة. الأسئلة لا تتكرر
  عبر الجولات إلا بعد استنفاد البنك المختار.
- الصح 20؛ الخطأ أو عدم الإجابة صفر. لو الاتنين صح في نفس السؤال، 10 لكل واحد
  في وضع نص الدرجة، أو 20 في وضع الدرجة الكاملة، حتى مع اختلاف وقت الإجابة.
- الترتيب بالنقاط ثم أقل متوسط **أوقات الإجابات الصحيحة فقط**. التطابق الكامل
  يعطي نفس المركز. الحساب بالمللي ثانية من بداية السؤال إلى وصول الإجابة للسيرفر،
  ويتأثر بزمن الشبكة. ساعة الهاتف لا تحدد التصحيح أو النتيجة.
- الأسماء والإجابات نص حر. التطبيع يعالج المسافات والتشكيل والهمزات والأرقام العربية؛
  لا يصحح خطأ إملائيًا تخمينيًا. الإجابات البديلة مسجلة صراحة في البنك.
- الأدمين هو منشئ الغرفة. يقدر يعتمد أو يلغي صحة إجابة مكتوبة بعد كشف السؤال،
  بما فيها أسئلة سابقة والنتيجة النهائية، بسجل ظاهر للاعبين. النص والوقت الأصلي
  ثابتان، وتتحدث كل النقاط والسرعة والترتيب فورًا. لا يمنح نقاطًا لإجابة غير مرسلة.
- لا تُرسل إجابة السؤال الصحيحة ولا إجابة الخصم قبل انتهاء السؤال.
- قبل البدء يستعد اللاعبَان؛ صاحب الغرفة ينقل للسؤال التالي بعد المراجعة.
  فصل لاعب لا يوقف وقت السؤال. انتقال السؤال التالي يتطلب رجوع اللاعبَين.
- المباراة محفوظة على السيرفر ومفتاح الرجوع على نفس الموبايل. الغرف غير النشطة
  تحذف بعد 48 ساعة. حفظ المفتاح لا يغني عن الاحتفاظ بنفس بيانات التطبيق.
- المفاتيح عشوائية، المخزن يحتفظ ببصمتها فقط؛ صلاحيات التعديل من هوية الاتصال،
  مع حدود لحجم الرسالة والطلبات وعدد الاتصالات والغرف. النظام صُمم لغرف خاصة
  بين أصدقاء؛ كود الغرفة دعوة للدخول ويُشارك فقط مع اللاعب المقصود.

## التحقق قبل النشر

`npm test` يختبر القواعد واتصال عميلين حقيقيين، إخفاء الإجابات، رفض تعديل الضيف،
تعديل التصحيح والنقاط، حفظ الغرفة وإعادة تشغيل السيرفر والرجوع بمفتاحها.
اختبارات Flutter تشمل شاشة صغيرة والإجابات المكتوبة وصلاحيات الواجهة.
النشر العام واختبار مكالمة موبايلين يحتاجان حساب الاستضافة وخدمة TURN؛
لمجرد وجود الملفات لا تعتبر الخدمة منشورة أو المكالمة متحققة على شبكة عامة.
